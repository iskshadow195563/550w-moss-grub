# 验证记录

验证日期：2026-10-08（Asia/Shanghai）。

## 安装与恢复

在 WSL 的 Kali Linux 里只跑临时目录的模拟安装。测试副本把所有系统路径指向临时文件系统，没有动 WSL 或电脑上的 `/boot`、`/etc/default/grub`、EFI 分区。GRUB 工具和 QEMU 从发行版软件包解到临时工具目录，没有安装系统软件包。

`tests/test_install.py` 的 14 个用例全过，生成的 GRUB 配置用真实的 `grub-script-check` 检查过：

- 默认安装保留默认系统和 Windows / Linux 启动项。
- 预检查和非法参数不写系统。
- 生成失败、语法错误、主题缺失、Windows 入口丢失、Linux 入口丢失，都还原原配置。
- 独立 `/boot` 分区用的 GRUB 相对路径能通过检查。
- 拒绝覆盖不属于本包的主题。
- 重复安装能换布局；升级失败回到上一版主题和配置。
- 卸载按当前内核重新生成配置；卸载失败还原主题设置。

所有 Bash 脚本过 `bash -n`。`tests/check_assets.py` 检查 PF2 真实字体名、常用汉字和标点覆盖、五个主题文件的字体和九宫格素材引用，全过。

## 真实 GRUB 预览

预览跑在 QEMU 11.1 的软件模拟上，SeaBIOS 加 GNU GRUB 2.14-2+kali1。虚拟机只挂本项目的演示 ISO，不挂真实硬盘。截图直接来自 GRUB 图形输出。

用 QMP 键盘事件测了主菜单选择、中文高级选项子菜单、长子菜单滚动、Esc 返回和 C 命令行。截图在 `preview-分辨率-场景.png`。演示菜单倒计时设 30 秒方便截图，正式安装是 8 秒。

720p、1080p、1440p、4K 的实际输出分别是 1280×720、1920×1080、2560×1440、3840×2160。预览脚本按布局设置 `gfxterm_font`，避免一次加载所有字体后 GRUB 挑了大字号、低分辨率起不来图形终端。这些模式在你电脑上能不能用，看固件。

`tests/check_captures.py` 对四种分辨率的截图检查像素尺寸、红色高亮从 Ubuntu 移到 Windows、倒计时区域变化、子菜单滚动，全过。

## 验证范围

预览里的 Windows / Ubuntu 条目只是演示文字，不会启动系统。没有在真实 Ubuntu 上装过主题、重启过，也没验证两个系统的实际启动。固件的 4K 图形模式、Secure Boot、磁盘加密都没测。主题包只用原有系统入口，安装时会重新检查配置。

背景实际像素 1672×941，4K 布局会放大它。源参考图的 3840×2160 版本在源码 `assets` 里。

## 2026-10-23：跨电脑显示兼容修订

用户报告：用原脚本装完后，同一次开机里等待或切换选项，菜单会突然只剩一个很大的图标，还能继续切换。只有照片，没连那台电脑，也不知道实际图形模式。

改动：新增 `--safe-mode` 紧凑布局，图标 24 像素、行高 32 像素、边框切片 4 像素。只装当前布局要的字体和 CJK 14 控制台字体。`/etc/grub.d/00_550w_moss_font` 输出 `set gfxterm_font="MOSS CJK Regular 14"` 和 `export gfxterm_font`，按名字排序排在 `00_header` 前面跑。新脚本和主题、配置片段一起参与升级、失败还原和卸载。

- 用 Ubuntu 官方 `grub-common` / `grub-pc-bin` 2.12-1ubuntu7.3 的 GRUB 模块，在没有真实硬盘的 QEMU / SeaBIOS 虚拟机里检查。
- 1920×1080 下测了等待、连续切换 12 次、C 命令行、Esc 返回、退出演示项回到菜单，布局正常。用户说的完整触发过程没复现。
- 强制 640×480 走同样流程：四个启动项的图标同时可见，选中框没撑满菜单。截图是 `compat-640-initial.png`、`compat-640-switched.png`、`compat-640-returned.png`、`compat-640-entry-returned.png`。
- `tests/check_captures.py` 对这四张低分辨率截图检查像素尺寸、四行图标是否可见、选中区域高度。
- 安装事务测试从 14 项加到 17 项，全过：新增安全模式字体隔离、生成配置漏字体锁时的回滚、拒绝覆盖非本包字体脚本。原有升级失败和卸载失败用例也检查字体脚本还原。
- 字体和素材引用检查、Bash 语法检查、最终 ZIP 的字节、LF 换行、可执行权限、完整性检查都过。

结论：确认了字体选择和低分辨率布局的风险，并给出可验证的安全模式。那台电脑上的具体触发原因还没定位，要实际装一次修订包确认。UEFI、Secure Boot 和真实系统启动不在这一轮虚拟机验证里。
